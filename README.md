# HRMS（人材管理システム）

## 概要
社内の人材・部署情報を管理するための Web アプリケーションです。  
未経験から Web 系 Java エンジニアを目指すにあたり、  
**実務で頻出する「マスタ管理（部署管理）」を題材に、設計から実装までを一通り経験すること** を目的として作成しました。

CRUD 処理、画面遷移、バリデーション、エラーハンドリングなど、  
業務アプリケーションで基本となる要素を実装しています。

---

## 使用技術
- Java 17  
- Spring Boot  
- Spring Data JPA  
- PostgreSQL  
- Thymeleaf  
- Maven  

※ 実務での利用頻度が高い構成を意識して選定しました。

---

- 部署新規登録

- 部署削除（論理削除）  
- 処理結果メッセージ表示  

---

## 画面一覧
- 部署一覧画面  
- 部署登録画面  
- 部署編集画面  

---

## 設計

## 工夫点
- JPA 利用時に、Entity と DB 定義の不整合によるエラーを実際に経験  
  → 主キー設計を見直し、Entity・Repository・DB 定義を統一  
  → **設計段階での整合性の重要性を理解**
- Controller に処理を集中させず、Service 層を設けて責務分離を意識  
  → **処理の見通しと保守性を向上**

  → **業務アプリケーションでのユーザー体験を意識**

## 画面遷移（部署一覧）

| 操作 | 遷移先 | 備考 |
|----|----|----|
| 新規 | 部署登録画面 | 新規部署作成 |
| 編集 | 部署編集画面 | 既存部署更新 |
| 削除 | 部署一覧画面 | 確認ダイアログ＋結果表示 |
| 戻る | ダッシュボード | |

---

## 処理フロー（部署一覧画面）

1. ユーザーが部署一覧画面にアクセス  
2. Controller がリクエストを受け取り、Service 層に一覧取得を依頼  
3. Service 層が Repository を通じて DB から部署情報を取得  
4. Controller が取得結果を Model に格納  
5. View（Thymeleaf）で部署一覧を表示  

---

## 編集・削除機能
- 部署一覧画面から編集・削除が可能  
- 削除時には確認ダイアログを表示し、誤操作を防止  
- 削除操作は視覚的に区別できるよう、削除アイコンを使用
