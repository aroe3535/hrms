# HRMS（人材管理システム）

## 概要
社内の人材・部署情報を管理するためのWebアプリケーションです。
未経験からWeb系Javaエンジニアを目指すにあたり、
実務で頻出する「マスタ管理（部署管理）」を題材に、
設計〜実装まで一通り経験することを目的として作成しました。

CRUD処理、画面遷移、エラーハンドリングなど、
業務アプリケーションで基本となる要素を実装しています。

## 使用技術
- Java 17
- Spring Boot
- Spring Data JPA
- PostgreSQL
- Thymeleaf
- Maven

※ 実務での利用頻度が高い構成を意識して選定しました。

## 工夫点
- JPA利用時に、EntityとDB定義の不整合によるエラーを実際に経験し、
  主キー設計を見直すことで Entity・Repository・DB の定義を統一した  
  → 設計段階での整合性の重要性を理解できた
- Controllerに処理を集中させず、Service層を設けて責務分離を意識  
  → 処理の見通しと保守性を向上
- 削除処理時に、成功・失敗それぞれのメッセージを返すことで、
  ユーザーに処理結果が分かる実装を行った

### 画面遷移（部署一覧）

| 操作 | 遷移先 | 備考 |
|----|----|----|
| 新規 | 部署登録画面 | 新規部署作成 |
| 編集 | 部署編集画面 | 既存部署更新 |
| 削除 | 部署一覧画面 | 確認ダイアログ＋結果表示 |
| 戻る | ダッシュボード | |


## 処理フロー（部署一覧画面）

1. ユーザーが部署一覧画面にアクセスする
2. Controller がリクエストを受け取り、Service 層に一覧取得を依頼
3. Service 層が Repository を通じてDBから部署情報を取得
4. Controller が取得結果を Model に格納
5. View（Thymeleaf）で部署一覧を表示

## 編集と削除
- 部署一覧画面に編集・削除機能を実装
- 削除操作時には確認ダイアログを表示し、誤操作防止を考慮
- 削除操作は誤操作を防ぐため、リンク色を赤にして視覚的に区別


## 作成意図
未経験からWeb系Javaエンジニアを目指す中で、
**実務を想定した開発フローを経験すること**を目的に作成しました。

公式ドキュメントや一般的な実装例を参考にしつつ、
「なぜこの実装になるのか」を理解しながら構築しています。

特に以下の点は、自身で調査・試行錯誤しながら実装しました。
- EntityとDB設計の整合性
- Service層による責務分離
- エラー発生時の原因特定（JPA・SQL）
